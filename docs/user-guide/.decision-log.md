# Documentation decisions

## 2026-11-26 — Create, exhaustive, headless

- Code baseline: `a5fcc38`. The examples target the public `0.1.0` release at
  `1415a8c608780ac82fd2985e47de03fc8bea9528`.
- Primary audience: TypeScript developers who use the package in an Effect v4
  application. The first text result through `AiSdk` is the first tutorial.
- Use `docs/user-guide` to keep the user guide separate from the development
  standards, review rules, and existing machine-readable SDK inventory.
- Group the API by import family. The import reference lists every package
  subpath. The versioned SDK inventory supplies exact pinned symbol names and
  resolution data. The package declarations supply the wrapper signatures.
- Keep build and release work in the contributor section. Keep experiment logs,
  private bridge modules, and temporary proof fixtures out of the user guide.
  Include the import conditions and peer dependencies that affect consumers.
- Use local model fixtures for the tutorials so readers can run them without
  network credentials. Provider guides cover application configuration.
- The user requested the Ensure Docs and Diátaxis workflows and the shared skill
  copy. Use English and the full page map, with no curated deferrals.
